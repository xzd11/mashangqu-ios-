# 码上取 iOS 1.0.3

多平台身份码与快递聚合应用。

> 社区编译版本，使用 AI 编写。此前版本仅在 iPhone 15 上验证使用，1.0.3 新功能已通过自动化检查，待真机验证。

## 功能

- 拼多多 App 扫码授权登录，二维码可保存至相册，二次验证由官方页面完成。
- 淘宝 / 菜鸟、拼多多、京东、顺丰、如意邻里账户管理与身份码。
- 身份条形码横向全屏展示；旋转屏幕时自动调整，过期时停止展示。
- 快递聚合、平台筛选及运单合并。
- 按快递运单号通过菜鸟查询取件码。
- 每条快递卡片提供「通过菜鸟查询取件码」按钮，显示查询结果及来源。
- 可选前台自动刷新；主界面固定缩放，避免双击误放大。
- 登录凭据和缓存保存在本机钥匙串，请求直连平台。

京东目前支持身份码，暂不支持快递列表。菜鸟查询使用当前登录账户，查无结果、已取件或仅脱敏时会明确提示。

## 安装与升级

安装包：`Mashangqu-iOS-1.0.3-self-sign.ipa`。

支持 iPhone / iPad，最低 iOS / iPadOS 15.0，ARM64 真机。使用自己的工具重新签名后安装；升级时沿用同一签名身份和 Bundle ID `ink.mashangqu.ios` 覆盖安装，可延续账户与缓存。

## 本次发布

1.0.3（构建 12）将拼多多扫码后的短信、文字单选／多选、图片选择题接入软件内的统一样式验证界面。用户手动输入验证码或选择答案，验证通过后继续原扫码会话。答错提示重试，选择题答错时按服务端要求加载下一题。滑块、拼图、未知类型或内置验证失败可使用官方验证页面。

验证 UI 位于本地 WKWebView 中，与现有软件界面一致，不加载平台网页。密钥交换及 AES 加解密使用 iOS Security／CommonCrypto，临时密钥仅保存在内存，不存入钥匙串或应用缓存；关闭验证窗口后清理会话。RSA 公钥和请求流程沿用上游实现。不会自动回答题目或绕过平台安全验证。

新增验证流程已通过模拟接口检查和原生编译／ABI 检查；由于没有真实账户完成扫码，本版内置验证和是否保持拼多多客户端在线仍需真机验证。


1.0.2（构建 11）移植上游 `PddQrClient.kt` 的拼多多 AUTH_LOGIN 扫码授权流程（app_id 512）。默认入口改为「扫码登录」，不走普通手机号登录；使用拼多多 App 扫一扫、从相册选择二维码后确认。支持系统分享菜单保存二维码、过期自动重新生成、取消后忽略迟到结果。平台要求二次验证时，打开携带原扫码会话参数的官方 `psnl_verification.html` 页面，由用户手动完成验证，点击「完成登录」读取凭据。

真实匿名生成二维码请求返回 HTTP 200，包含二维码与会话密钥。未使用用户账户完成授权，因此客户端是否保持在线需用户真机验证。


1.0.2（构建 10）新增「已取」按钮，快递卡片和独立查码结果均可使用。点击后删除本机取件码并从待取列表移除；本机保存按平台账户区分的已取标记，刷新和重新启动不会恢复旧码。此操作不修改平台取件状态。保存失败时恢复原记录并提示失败。

## 源码与构建

- `native/main.m`：原生 iOS 容器、钥匙串、网络桥接、码图生成。
- `native/AppleABI.h`：最小公共 ABI 声明。
- `web/`：本地界面和平台适配逻辑。
- `test_abi.py`：编译对象和 IPA 对象布局检查。

Linux 安装 `requirements.txt`，并准备 LLVM `ld64.lld`（可通过 `MSQ_LD64` 指定），执行：

```
python build_native.py
python package_ipa.py
```

构建只使用系统符号链接声明，不分发 Apple SDK 或系统框架。Mac 上也可定义 `MSQ_USE_SDK`，用 Apple SDK 编译主程序。
