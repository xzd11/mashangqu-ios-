## 0.1.7 固定页面缩放与横向条形码展示

主界面 viewport 固定为 1 倍，使用 touch-action:manipulation 抑制双击缩放，并关闭主 WKWebView 的捏合识别；文本域改为至少 16px，避免输入时触发自动缩放。平台官方登录网页保持自身行为。

主页点击条形码后使用白底全屏查看器。竖屏时码图和查看器控件旋转 90 度，沿屏幕长边显示；横屏时使用自然横向布局。此处通过视图旋转实现，不强制更改 iOS 系统方向锁定。二维码类型仍按方形显示，未将条形码改为二维码。

查看器显示平台、码值和有效时间，提供关闭按钮；旋转屏幕时重排，已过期时停止展示码图并提示关闭后刷新。

浏览器中已检查固定缩放配置、纵横屏布局、关闭与过期；iOS 手势与真实扫码仍需设备验证。

## 0.1.6 快递卡片一键查询

每张快递卡片新增「通过菜鸟查询取件码」。点击自动使用该条记录的快递运单号；未登录菜鸟时打开账户登录窗口。无真实运单号的校园记录禁用按钮并说明原因。查询期间禁用重复操作。

成功查询的完整码显示在对应卡片，标明来自菜鸟，并作为带菜鸟账户标识的补充结果缓存；保留原平台码，换菜鸟账户或退出后不展示旧账户的补充码。失败或仅脱敏时在卡片内显示状态。顶部手输运单号查询保留。

## 0.1.5 快递页按运单号查询菜鸟取件码

快递页顶部新增输入框。先登录淘宝 / 菜鸟，输入快递运单号后点击「查询取件码」，结果显示完整码、驿站、来源和查询时间。

查询流程移植自上游 TaobaoAdapter.fetchPickupCode：列表最多 3 页找完整码；未命中调用 multiOneSearch 确认状态；待取件时再次从列表取完整码。multiOneSearch 的脱敏码不用于展示；status 3 为待取、4 为已取，不依赖不可靠的 pickedWaybill 标志覆盖状态。

分别处理查无结果、已取件、只返回脱敏码、登录失效和网络错误。输入会去掉空白并转大写；查询使用当前菜鸟账户，不保证任意运单都能返回取件码。结果仅保留在当前界面内存中，切换账户后隐藏。购物平台订单号不等同于快递运单号。

接口固定响应与移动页面交互测试通过；真实菜鸟账户的查询结果仍需用户设备验证。

## 0.1.4 菜鸟身份码类型

按用户最新更正，将淘宝 / 菜鸟身份码改为 Code128 条形码，使用现有原生条形码生成器；卡片采用横向条码布局。保留此前的登录布局和拼多多刷新修正。设置页版本显示同步为 0.1.4。

## 0.1.3 顺丰 / 京东登录布局

用户补充顺丰、京东也出现登录界面异常。现在拼多多、顺丰、京东共用避开状态栏与导航栏的登录容器：网页作为根视图随系统布局、不扩展到导航栏下，使用不透明导航栏。淘宝保留原先已正常使用的布局；0.1.2 的拼多多刷新修正保留。

已通过交叉编译、IPA 结构和对象布局检查；三平台原生页面仍需用户设备复测。

## 0.1.2 拼多多登录与刷新修正

用户确认 0.1.1 已能启动、淘宝可使用；拼多多登录页顶部被导航栏和状态栏遮挡，身份码刷新失败。

- 仅调整拼多多原生登录窗口：不向导航栏下延伸，WKWebView 作为根视图，使用不透明导航栏，随容器自动布局；淘宝登录窗口保持现有行为。
- 拼多多校验 worker 加入主视图后方，避免脱离视图树带来的 WebKit 暂停问题；这是针对运行机制的修正，未在用户设备验证效果。
- 原生 20 秒超时、页面加载失败与结果返回都会清理 worker，防止一次失败后永久卡住。
- 支持 PDDAccessToken / pdd_access_token / accesstoken 三种凭据字段；未取得凭据时保留登录窗口并提示继续登录。
- expire_mills 兼容剩余毫秒、Unix 秒和 Unix 毫秒，避免将剩余时间误判为已过期。
- 显示 PDD-ANTI-*、PDD-40001、PDD-70005、PDD-54001 等错误阶段，便于截图排查；不记录或显示账户凭据。

0.1.2 的原生布局、平台登录与接口结果仍需真机复测；不能仅凭模拟测试宣称平台兼容性已验证。

## 0.1.1 启动修复

0.1.0 的真机崩溃日志显示启动回调设置 window 时进入 object_setClass。交叉编译声明遗漏 NSObject 的 isa 指针，使 MSQDelegate._window 编译偏移为 0。现补全对象头，编译偏移为 8；已对编译对象与最终 IPA 增加 ABI 检查，旧包能触发失败，新包通过。

此修复针对已知启动崩溃；用户后来确认 0.1.1 可以启动。

## 安装

`Mashangqu-iOS-0.1.7-self-sign.ipa` 是 ARM64 真机安装包，最低 iOS / iPadOS 15.0。
包内只有构建用的 ad-hoc 签名，没有 Apple 开发证书和描述文件。请用自己的签名工具重签整个应用并安装。
不需要电脑上运行 Android，也不是 APK 改后缀。

这是新写的原生 iOS 容器 + 本地业务界面的实验移植，**不是经过真机验证的原安卓应用完整等价版本**。
0.1.0 已由用户安装并报告启动崩溃；用户已确认 0.1.1 能启动且淘宝正常；0.1.2 为拼多多问题修正包，尚未获得该版真机运行结果，也未使用真实账户验证登录、验证码、取码或驿站扫描。自签成功不等于业务功能已经验证成功。

| 平台 | 身份码接口 | 登录入口 | 快递列表 | 尚未验证 / 缺失 |
| --- | --- | --- | --- | --- |
| 淘宝 / 菜鸟 | MTOP H5 签名与 token 重试 | 官方网页登录 / 导入完整 Cookie | 按站点解析，最多 5 页 | 原安卓协议短信登录、多账号选择、风险页收尾未移植；网页登录可能被风控阻止 |
| 京东 | generateIdentityCode，Code128 | 官方网页登录 / pt_key + pin 导入 | 未实现，沿用上游限制 | 网页不一定下发 pt_key；原安卓 Jcap 短信链路未移植 |

不支持：安卓 APK 自动更新、YYB 微信换链、后台定时刷新、原生分享或复制日志。

## 数据与网络

- 账户凭据和包裹缓存保存到本机 Keychain，不写入浏览器 localStorage。
- 全部 API 请求通过 NSURLSession 直连对应平台，保留系统 TLS 验证。
- 官方登录页使用单独的临时 WKWebView，不具备本地业务界面的桥接权限。
- 本地界面的原生桥接仅接受应用本地文件的主 frame；HTTP 请求仅开放代码列出的平台域名。
- 删除账户会删除本机钥匙串对应账户记录；不代表撤销平台服务器上的会话。
- 不含账户、证书、描述文件、个人 Cookie 或遥测。

## 源码与构建

`native/main.m` 为原生主程序；`native/AppleABI.h` 为自行声明的最小公共 ABI；`web/` 为本地界面和业务适配器。
`web/pdd.js` 保留上游 MIT 校验模块。

### Linux 交叉编译

安装 Python 包 `ziglang==0.13.0`，并安装 LLVM `ld64.lld`，设置 `MSQ_LD64` 指向该程序（如它不在 PATH）。

```
python build_native.py
python package_ipa.py
```

构建脚本生成只包含系统符号名称的链接 stub，**不打包苹果框架或 SDK**。所有系统 API 实现由设备上的 iOS 提供。
`package_ipa.py` 使用已随源码附带的应用图标生成安装包。无需上游安卓工程参与构建。

也可以在 Mac 上用正常 Apple SDK 编译 `native/main.m`（定义 `MSQ_USE_SDK`），链接 UIKit、WebKit、CoreImage、Security、Foundation、CoreGraphics，使用相同 Info.plist 与 web 资源；本源码未附带 Xcode 工程。
